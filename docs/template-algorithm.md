# Подготовка и обработка текстовых шаблонов

## Условия BIL24

Приложение использует три текстовых шаблона размером примерно 500 КБ и обслуживает
несколько сотен запросов в день. В каждом запросе значения клиента подставляются в
якоря шаблона. Фиксированная интерпретация размера в тестах — ровно 512 000 байт в
UTF-8. Решение использует только стандартную библиотеку Java и не добавляет веб-сервер:
это пример интеграции алгоритма в существующее приложение.

## Принятые правила

Якорь соответствует выражению `<([A-Za-z_][A-Za-z0-9_]*)>`, а ключ в `Map` передаётся
без угловых скобок. Регистр значим. Текст вне совпадений сохраняется буквально, поэтому
`<<name>>` при `name=Ира` превращается в `<Ира>`. Отсутствующий ключ оставляет якорь,
пустое значение удаляет его, а `null` для используемого ключа вызывает
`IllegalArgumentException` с именем ключа. Лишние ключи, в том числе со значением
`null`, не читаются.

Подстановка однократная и буквальная: символы `$`, `\`, переводы строк и похожие на
якоря значения не имеют специального смысла. `null` вместо исходного текста или
таблицы замен вызывает `NullPointerException`. `render` не изменяет таблицу; вызывающий
код, в свою очередь, не должен менять её во время вызова. HTML-экранирование не входит
в алгоритм: при выводе в HTML его выполняет вызывающее приложение с учётом контекста.

## Загрузка трёх файлов

Пути являются конфигурацией приложения, например параметрами командной строки:

```java
Path welcomePath = Path.of(args[0]);
Path reminderPath = Path.of(args[1]);
Path receiptPath = Path.of(args[2]);
```

При запуске приложение читает все три файла в UTF-8 и подготавливает каждый шаблон:

```java
Map<String, CompiledTemplate> templateMap = Map.of(
    "welcome", CompiledTemplate.compile(Files.readString(welcomePath, StandardCharsets.UTF_8)),
    "reminder", CompiledTemplate.compile(Files.readString(reminderPath, StandardCharsets.UTF_8)),
    "receipt", CompiledTemplate.compile(Files.readString(receiptPath, StandardCharsets.UTF_8)));
String response = templateMap.get("welcome")
    .render(Map.of("user_name", "Ира", "area_name", "Большой зал"));
```

Этот фрагмент выполняется в методе запуска, который объявляет `throws IOException`,
либо внутри обработчика стартовой ошибки. На практике каждый путь загружают через
маленький метод, который при `IOException` добавляет проблемный путь в сообщение и
прерывает запуск:

```java
static CompiledTemplate loadTemplate(Path path) {
  try {
    return CompiledTemplate.compile(Files.readString(path, StandardCharsets.UTF_8));
  } catch (IOException exception) {
    throw new IllegalStateException("Не удалось загрузить шаблон: " + path, exception);
  }
}
```

Приложение не должно начинать обслуживание с одним или двумя шаблонами: ошибка чтения
любого файла означает ошибку запуска с указанием этого файла. После успешной загрузки
исходные файлы больше не нужны для обработки запросов. Их последующее изменение или
удаление не меняет уже подготовленные объекты; чтобы применить новое содержимое, нужно
явно перечитать и заново подготовить шаблоны.

## Подготовка

`CompiledTemplate.compile` один раз находит якоря регулярным выражением и сохраняет
чередующиеся литералы и якоря в неизменяемой последовательности сегментов. У якоря
хранятся исходный текст и имя ключа, поэтому при отсутствии значения можно вернуть
исходную запись. Подготовленные объекты сохраняются в `templateMap` на весь срок работы
приложения. Регулярное выражение после запуска при обработке запросов не выполняется.

## Обработка запроса

Обработчик выбирает готовый объект по имени и вызывает `render` со своей таблицей
значений. Метод проходит по сегментам, добавляет литерал, найденное значение либо
исходный якорь в новый локальный `StringBuilder`, а затем возвращает отдельную строку.
Он не читает файлы, не запускает регулярное выражение, не сохраняет и не изменяет
таблицу запроса.

## Конкурентность

`CompiledTemplate` неизменяем после `compile`: последовательность сегментов и строки в
ней не меняются. Все изменяемые данные рендера — локальный `StringBuilder` и переданная
конкретному вызову `Map`. Поэтому один подготовленный шаблон можно одновременно
использовать в разных потоках с разными данными клиентов, и значения одного запроса не
переходят в следующий. Контракт предполагает, что сама переданная `Map` не изменяется
параллельно во время вызова.

## Затраты

Пусть `N` — число символов исходного шаблона, `A` — число вхождений якорей, а `R` —
число символов результата. Для выбранной простой грамматики подготовка проходит
исходник за линейное время, а подготовленный шаблон занимает `O(N + A)` памяти.

При обычной стоимости lookup в `Map` обход сегментов и сборка результата стоят
`O(A + R)`. Реализация заранее резервирует в `StringBuilder` вместимость `N`, поэтому
полная стоимость одного запроса с выделением буфера — `O(N + A + R)`, а временная
память — `O(N + R)`. Готовую строку длины `R` всё равно необходимо создать; кэширование
подготовленного шаблона эту стоимость не устраняет.

## Ограничения

Оценка lookup предполагает обычную, в среднем постоянную стоимость реализации `Map`.
Алгоритм работает с обычным текстом и не поддерживает условия, циклы, вложенный язык
шаблонов или контекстное HTML-экранирование. Изменения файлов не подхватываются
автоматически.

При нескольких сотнях запросов в день выигрыш от исключения повторной подготовки может
оказаться практически несущественным. Для такого трафика особенно важны простота и
предсказуемость решения: три файла читаются один раз, а каждый запрос выполняет один
прямой проход по неизменяемому представлению.
