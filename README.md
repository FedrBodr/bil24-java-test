# BIL24 · Java test assignments

[PR №1 — код для ревью](https://github.com/FedrBodr/bil24-java-test/pull/1)

Решение двух [публичных тестовых заданий BIL24](https://bil24.pro/vac_java_dev.html): оптимизация парсера мест и подстановка значений в неизменяемые текстовые шаблоны.

**Реализация подготовлена к финальному ревью владельца.** Спецификация и планы одобрены до написания кода. Проверки совместимости, многопоточности и полные измерения JMH сохранены вместе с решениями.

## Сборка и проверка

Нужны JDK 17 или 21 и Python 3 для получения эталона. Maven 3.9.9 загружает Wrapper; первый запуск требует доступа к Maven Central.

```sh
git clone https://github.com/FedrBodr/bil24-java-test.git
cd bil24-java-test
git checkout feat/java-solutions
./mvnw clean verify
```

Обычная сборка проверяет две основные библиотеки. Для полной проверки совместимости с оригиналом BIL24:

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/fetch_reference.py
./mvnw -Pcomparison clean verify
```

Скрипт проверяет SHA-256 архива и меняет только объявление пакета эталона. Повторный запуск использует проверенный локальный архив. Если эталон не подготовлен, профиль `comparison` завершается с командой его получения.

Проверено: 111 Java-тестов и 5 Python-тестов; [CI на JDK 17 и 21](https://github.com/FedrBodr/bil24-java-test/actions/runs/35141585409) завершился успешно.

В основных библиотеках используются только классы JDK. JUnit 5.11.4 относится к тестам, JMH 1.37 — к отдельному модулю измерений. Исходный и целевой уровень Java — 17; CI проверяет JDK 17 и 21.

## Задание 1: парсер мест

[ParserSeat.java](seat-parser/src/main/java/test/ParserSeat.java) сохраняет исходные API, регулярное выражение и семантику `find()`. Основные изменения:

- `Pattern` компилируется один раз; каждый вызов создаёт собственный `Matcher`.
- Результат создаётся после успешного совпадения.
- Двенадцать кириллических букв заменяются за один проход по имени сектора; буфер создаётся при первой замене.

[ResultParser.java](seat-parser/src/main/java/test/ResultParser.java) сохраняет изменяемые поля, конструктор, getter/setter-методы и вычисляемые названия. Пробелы, регистр и пустые значения обрабатываются как в оригинале; несовпадение возвращает `null`, вход `null` вызывает `NullPointerException`.

Проверки: [контракт и DTO](seat-parser/src/test/java/test), [10 000 детерминированных сравнений](benchmarks/src/test/java/com/fedrbodr/bil24/benchmark/ParserDifferentialTest.java), [8 000 параллельных сравнений](benchmarks/src/test/java/com/fedrbodr/bil24/benchmark/ParserConcurrencyTest.java). Сравниваются все семь полей и три вычисляемых названия.

## Задание 2: текстовые шаблоны

[CompiledTemplate.java](template-renderer/src/main/java/com/fedrbodr/bil24/template/CompiledTemplate.java) один раз разбирает исходник на неизменяемые части. Каждый запрос использует свою таблицу и локальный буфер:

```java
CompiledTemplate template = CompiledTemplate.compile("Привет, <user_name>!");
String response = template.render(Map.of("user_name", "Ира"));
// Привет, Ира!
```

Ключи соответствуют `[A-Za-z_][A-Za-z0-9_]*`, регистр значим. Отсутствующее значение сохраняет якорь, пустое удаляет его, используемый `null` вызывает ошибку с именем ключа. Подстановки буквальные и однократные.

[Объяснение алгоритма и пример загрузки трёх файлов](docs/template-algorithm.md) · [тесты](template-renderer/src/test/java/com/fedrbodr/bil24/template). Проверяются три файла ровно по 512 000 UTF-8 байт, работа после их удаления и 800 параллельных рендеров.

## Измерения до и после

На Apple M3 Max / Corretto 21.0.6 в одном потоке:

- Парсер, латиница: **1 421,61 → 621,38 нс/операцию**, отношение 2,29×.
- Парсер, кириллица: **1 716,98 → 659,69 нс/операцию**, отношение 2,60×; выделения 5 808 → 1 120 B/op.
- Шаблон с 10 якорями: **1 321,93 → 39,36 мкс/рендер**, отношение 33,58×. Для 100 якорей — 24,83×.

Доверительные интервалы этих пар не пересекаются. Полные таблицы включают все сценарии и разброс измерений.

[Полные таблицы, исходные JSON и логи](docs/results/README.md) · [методика и команды](docs/benchmark-methodology.md).

Парсер сравнивается с зафиксированным оригиналом BIL24. Для шаблонов сравниваются два наших способа обработки: подготовка при каждом запросе и однократная подготовка при загрузке. Отдельно измерена стоимость самой подготовки.

JMH: 3 отдельных JVM, 5 × 1 с прогрева и 5 × 1 с измерений; время операции, пропускная способность в 1/4 потока и B/op. Первоначальный запуск оригинала сохранён до оптимизации; итоговые отношения рассчитаны по повторному парному запуску.

Данные синтетические; распределение реальных запросов BIL24 неизвестно. В измерениях нет файлового I/O и сети, а исходная регулярка сохраняет ограничения на длинных некорректных строках. Среднее время операции не является p95/p99 задержки сервера.
